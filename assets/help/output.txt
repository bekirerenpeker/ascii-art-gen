asciigen -- output

Printing to the terminal is the default. Writing a file always has to be asked
for, and once you ask for one, printing stops unless you also pass --stdout.

  --out PATH                                              (none; prints)
      Write here. REPEATABLE -- every path given is produced from the one
      conversion. Format comes from the extension.

      Give an existing FOLDER instead of a file and it writes
      <folder>/<input name>.png. Convert a different picture and you get a
      different file, with nothing to rename and nothing to clash.

        asciigen assets/images/apple.png --out ./output
            -> ./output/apple.png

  --format EXT                                    (none; extension decides)
      Which format a bare-directory --out should use, so a filename never has
      to be spelled out just to pick one. Dot optional and case-insensitive
      ("png", ".png" and "PNG" all work); jpg and jpeg both accepted. Ignored
      whenever --out already names a real file -- that extension wins.

        asciigen photo.jpg --out ./output --format txt
            -> ./output/photo.txt

  --stdout / --no-stdout
      Force printing on or off, whatever else was asked for.

  --color MODE                                             (truecolor)
      truecolor | ansi16 | none

  --png-compression N                                              (8)
      0 fastest and largest, 9 slowest and smallest. Below 5 also skips stb's
      row-filter search, which is where most of the encoding time actually
      goes -- level 1 is about a third faster than 8 for ~9% more bytes.
      Always lossless, whatever the level.

  --overwrite                                                    (off)
      Allow replacing a file that already exists. Without it, an existing
      path is refused.


FORMATS

  .png .jpg     the glyphs drawn back into a picture. Honours --image-*
  .ans          text with colour escape codes. Displays in a terminal
  .txt          characters only, no colour

  A VIDEO input can also target .ans/.txt instead of a pixel container
  (.mp4 .mkv .mov .avi .webm .m4v) -- every frame one after another, in the
  same .ans/.txt shape as a still image's, with one metadata line (fps, frame
  count, duration) up front and a marker between frames. Not meant to be
  cat'd -- see --help input for what happens when one is given back in.


PICTURE SIZE

  --image-width N        output width in pixels
  --image-height N       output height in pixels
  --image-fit MODE       none | width | height | contain | cover | stretch
                                                            (contain)
  --image-align POS      top-left top top-right left center right
                         bottom-left bottom bottom-right      (center)
  --image-margin N       pixels kept clear on every side           (0)
  --image-scale F        art size as a fraction of what is left  (1.0)
  --image-aspect R       reshape the final picture, e.g. 16:9        (off)

  --image-scale    0.5  half size, lots of backdrop around it
                   0.7  a comfortable wallpaper inset
                   1.0  fill the box completely
  --image-margin   40   a visible border on a 1920-wide picture
                   120  a wide frame
                   Given in output pixels, so scale it with the picture.
  --image-aspect   16:9  widescreen     21:9  ultrawide
                   4:3   older screens  1:1   square

  --image-aspect only ever GROWS the picture: the short side is extended with
  backdrop. Nothing is cropped and the art is never resampled, so a square
  source becomes a 16:9 wallpaper at full glyph resolution instead of being
  squeezed to fit. Use it when you want a big sharp render in a given shape
  rather than a fixed pixel size:

    --font-render-size 64 --image-scale 0.5 --image-aspect 16:9

  Giving both --image-width and --image-height already fixes the shape, so
  --image-aspect is ignored then.

  margin, scale and align all work with no --image-width/--image-height:
  the canvas is then whatever the grid came out as.

  See --help sizing -- picture size, grid size and glyph size interact, and
  picture size wins.


EXAMPLES

  asciigen photo.jpg --out art.png --out art.ans --out art.txt
      all three from one conversion

  asciigen photo.jpg --out art.png --stdout
      write the file AND print it

  asciigen photo.jpg --out wall.png --image-width 1920 --image-height 1080
      exactly 1920x1080, scaled to fit, centred

  asciigen photo.jpg --out art.txt --color none --grid-width 100
      plain text, 100 characters wide

  asciigen photo.jpg --out wall.png --image-width 1920 --image-height 1080
                     --image-scale 0.6 --image-align top-left --backdrop auto
      art in the top-left corner at 60%, the rest left clear for icons
