asciigen -- algorithm

  --algo NAME                              ramp | bitmask | structure
                                                           (structure)

  ramp        cell brightness picks a character from an ordered list.
              Fast and simple. Needs an ordered charset -- see --help charset.

  bitmask     compares the glyph's ink against the cell, pixel by pixel.
              Solid all-rounder.

  structure   matches edge direction and ink placement as two separate
              things. Cleanest edges and the best surfaces. Default.


SHARED BY EVERY ALGORITHM

  --algo-allow-background                                        (off)
      Solve a second colour per cell instead of drawing on one backdrop.
      Much higher fidelity -- and it stops looking like text and starts
      looking like coloured blocks. Try it with --charset blocks.

  --algo-brightness-gamma F                                      (1.0)
      Below 1 brightens the foreground. See --help grid for why output is
      dimmer than the photo.
      0.7  strong lift     0.85  gentle     1.0  off

  --algo-ramp-chars "STR"                             (" .:-=+*#%@")
      The ordered list ramp steps through, light to dark.


--algo bitmask

  --algo-bitmask-softness F                                      (0.0)
      Blend a blurred match into the sharp one so a stroke sitting a pixel
      off still counts. Measured as unhelpful on real photos -- every value
      above 0 scored worse. Left in as a dial, not a recommendation.

  --algo-bitmask-blur-radius N                                     (1)
      How far a stroke may drift, in cell pixels. A cell is 8x16 at the
      default --font-match-size, so 2 is already a quarter of its width.
      Only does anything when --algo-bitmask-softness is above 0.
      1  default     2  loose     3+  shapes stop mattering


--algo structure

  --algo-structure-orientation-weight F                         (0.25)
      How much edge DIRECTION counts. This is the real dial.
      0    pure surface fidelity, softest
      0.25 balanced
      1.0  heavy outlines, and flat panels go mushy

  --algo-structure-mass-weight F                                 (1.0)
      How much WHERE THE INK SITS counts. This is what resolves shading.
      Read it against orientation-weight -- only the ratio matters.
      0.5  direction leads     1.0  balanced     2.0  placement leads

  --algo-structure-tone-weight F                                 (4.0)
      Pull toward glyphs whose ink coverage matches the cell's brightness.
      Both shape terms ignore how much ink there is, so without this you
      get the right shapes at the wrong exposure.

      Deliberately the largest of the three: getting brightness wrong is
      more obvious than getting a shape slightly wrong.
      1   shape wins, exposure drifts     4  default
      8   near enough a brightness ramp with shapes as a tie-break

  --algo-structure-orient-blocks WxH                             (2x4)
      Grid the cell is cut into before directions are counted. Coarse on
      purpose: pooling is what makes direction robust.

  --algo-structure-mass-blocks WxH                              (8x16)
      Grid for the ink-placement term. One pixel per block by default.
      Coarsening this is what makes T and -, or E and =, look alike to the
      scorer -- which is exactly how surfaces turn to mush.

  --algo-structure-bins N                                          (4)
      How finely direction is split, over a half turn. 4 bins is 45 degrees
      each, which is exactly what / | \ and - can express -- so finer
      binning describes angles no glyph can actually draw.
      4  default     8  finer, and slower for little gain
